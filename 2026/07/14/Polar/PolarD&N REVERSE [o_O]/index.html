Polar靶场

拿到附件是个mac c++文件，直接IDA打开，得到逻辑

好吧，我恨c++，反编译的c++阅读起来真是太痛苦了

可以看到关键的flag字符串，一个是假flag，一个是告诉我们最终flag格式是md5加密后的一串数组

程序逻辑是输入->加密->对比，先看对比环节，最终是和arr数组进行对比

arr数组的内容是0x5A, 0x14, 0xA, 0x32, 0, 0, 0x14，也就是90, 20, 10, 50, 0, 0, 20是七位，那么输入的也会是7位

看输入部分，将输入的内容给到v25，然后给到了字符串，在第一层加密中，最终传递的输入内容给到了v20

v19获得了v20-48的内容，48也就是ascii里的0，最后把v19的内容一个个push_back到v24vector数组里，stl反编译结果真难看啊

第二层加密

循环内部的逻辑看似是异或，研究发现其实是交换位置，这里用到了v27，而对v27定义的唯一处是在开头处，其实根本不用去算那个，因为既然知道最终是7位，然后要覆盖整个数组的话，遍历的最大限制肯定是6，那么v18=2*v27=6，v27就是3

测试下，代入j=0，就是交换vector[0]和vector[6]，j=1，就是交换vector[1]和vector[5]

可以看出来这是数组首尾反转，但是作者用了这种方式进行混淆

再下面，这里真是神了

v9被赋值了，所以v10=8 * v9+2 * v9=10 * v9，那其实就是把每一位乘10

最终arr是90, 20, 10, 50, 0, 0, 20，每位除10，得到9，2，1，5，0，0，2

首位交换为2，0，0，5，1，2，9，md5加密2005129，得到7e4e85033d36b28767243dcb3d9c7049

flag{7e4e85033d36b28767243dcb3d9c7049}
