什么是XSS？

​ XSS（跨站脚本攻击，Cross-Site Scripting）是一种攻击者在网页中注入恶意脚本代码的攻击方式。
​ 当其他用户浏览页面时，这些脚本会在用户的浏览器中执行，可能造成窃取用户信息、劫持账户、篡改页面等危害。
​ 常见的XSS测试方法就是通过alert弹窗来验证漏洞。

例如，把xss的poc放到链接里，里面有会拿走用户cookie发送到服务器的代码内容，用户点击，cookie被偷走就会被拿去盗用

POC（概念验证）：只验证漏洞是否存在。比如发送一个包含<script>alert(1)</script>的参数，如果弹窗了，就证明存在XSS漏洞，这个Payload就是POC

什么是反射型XSS？

​ 反射型XSS是指攻击载荷作为请求参数直接“反射”回页面并被浏览器立即执行。
​ 它的突出特点是无需持久存储，通常发生在网址参数、表单等用户即时提交数据，并在页面直接输出的情况下。
​ 反射型XSS常被用于钓鱼链接、伪造请求等场景，危害虽然通常只影响单次访问，但推广起来效率高。
​ 所有没有正确过滤用户输入并在页面直接输出的“立即返回型”功能，都可能存在反射型XSS风险。

什么是存储型XSS？

​ 存储型XSS是指用户提交的恶意脚本会被存储到服务器（如数据库、文件等），当其他用户访问相关页面时，这些脚本会被加载并在他们的浏览器中执行
​ 与反射型XSS不同，存储型XSS的危害性更大，通常用于留言、评论等功能不加过滤的情况下被攻击者利用。
​ 如本站的输入框，就是可以测试存储型XSS的靶场环境

什么是DOM型XSS？

​ DOM型XSS（Document Object Model Cross Site Scripting）是一种前端JavaScript代码在处理用户输入时，未对输入内容进行适当过滤或转义，导致恶意脚本被注入并执行的跨站脚本攻击方式。
​ 与反射型和存储型XSS不同，DOM型XSS的漏洞点主要在前端代码，攻击者通过构造特殊的输入，使得前端JavaScript动态生成的页面内容中插入了恶意脚本，从而实现攻击。
​ 例如：将用户输入直接拼接到 innerHTML、document.write 等API中，若未做安全处理，就可能导致DOM型XSS漏洞。

你输入 1 之前页面上没有这个元素。浏览器收到的 第一份源码（右键“查看网页源代码”）里如果没有 ，那么后来页面上却突然多出来一个可点的链接，一定是 JS 或前端模板在客户端动态生成的，不是服务器最初给的静态 HTML。而且是浏览器里的 JavaScript 监听了你的输入事件，然后动态创建了 和 并插进页面。这种“由脚本现场生成/改动后的页面结构”就是DOM 结果（虽然你没打开 F12，但原理一样：静态 HTML 自己不会长标签，必须脚本动手）
